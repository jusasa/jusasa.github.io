## 9장. 도메인과 용어사전의 정의

---

### 1. 데이터 표준화의 필요성 및 구성요소

* **데이터 활용상의 문제점**


* **데이터 중복 및 불일치**: 동일한 의미의 데이터가 서로 다른 명칭으로 중복 관리되거나 업무적 계산식이 상이하게 적용됨.


* **정보 제공 적시성 결여**: 데이터 의미 파악 지연으로 신규 정보 요건 대응이 어려움.


* **데이터 통합의 어려움**: 단위 시스템 위주의 표준 사용 또는 표준 부재로 전사 데이터 통합(EDW 등) 시 동일성 확인이 어려움.


* **유지보수 곤란**: 시스템 요건 변경에 따른 변경 영향도 파악이 난해함.




* **데이터 표준화 주요 구성요소**


* **표준 코드**: 특정 도메인이 미리 정의된 유형으로 값과 코드 명칭을 중복 없이 정의.


* **기타 요소**: 주제영역, 관계명, DB 스키마, 테이블 스페이스, 인덱스, 제약사항 등.





---

### 2. 도메인(Domain)의 정의

#### (1) 도메인의 개념

* **정의**: 엔티티의 속성들이 가질 수 있는 값들의 집합.


* **DBMS 관점**: 관계형 이론의 순수 도메인을 온전히 구현하기 어렵기 때문에, 대부분의 DBMS에서는 컬럼의 **데이터 타입(Data Type)과 길이**를 의미함.


* **동일 도메인의 의미**: 두 속성의 데이터 타입과 길이가 서로 같음을 의미함.



#### (2) 데이터 타입 지정 방식 비교

* **직접 지정 방식**: 테이블 정의 시 각 컬럼마다 데이터 타입을 개별 기재 (`empid int(7)`, `manager int(7)`).


* *문제점*: 시스템/테이블 간 동일 성격 컬럼의 데이터 타입 불일치 발생 가능 (예: 사원 테이블 `empid int(7)` vs 매출 테이블 `empid int(8)`).




* **도메인 사전 정의 후 사용**: `CREATE DOMAIN`을 통해 표준 도메인을 먼저 선언한 뒤 테이블 컬럼 타입으로 지정.



#### (3) 도메인이 덜 쓰이는 현실적 이유

* 도메인이 동일한 속성이 많지 않아 도메인의 수와 속성의 수가 거의 비슷해짐.


* 현실적으로는 공통 도메인이 여럿 존재하는 속성에 대해서만 선별적으로 도메인을 구축하고, 나머지는 직접 데이터 타입을 지정함.



#### (4) 도메인 도출 5단계 절차

1. **속성 리스트 수집**: 각 엔티티에서 속성들을 추출하여 목록 작성.


2. **단어 분리**: 속성명이 복합어인 경우 개별 단어 단위로 쪼갬 (예: `회원번호` $\rightarrow$ `회원` + `번호`).


3. **정렬**: 분리된 속성의 마지막 단어를 기준으로 정렬.


4. **도메인 지정**: 공통 분류에 맞춰 도메인명 부여 (예: `가입일자`, `구입일자`, `반납예정일` $\rightarrow$ `날짜` 도메인 / `탈퇴여부`, `반납여부` $\rightarrow$ `예아니오` 도메인).


5. **도메인 정리**: 중복 도메인을 병합하고 최종 데이터 타입 및 길이, 초기값, 값의 범위를 결정.

### 3. 용어사전(Data Dictionary)의 정의

#### (1) 용어사전의 개념 및 목적

* 논리적·물리적 데이터베이스 설계 시 사용되는 용어(엔티티명, 속성명)의 명확한 의미를 정의한 문서.


* 설계자마다 동일한 의미의 용어를 다르게 명명하여 발생하는 혼란 방지.


* 논리 설계(한글 명칭)에서 물리 설계(영문 명칭)로 전환 시 표준화와 통일성 유지.



#### (2) 용어사전 작성 절차

1. **단어 추출 및 수집**: 도메인 추출 방식과 동일하게 속성명을 단어로 분리하되, **엔티티 이름도 반드시 포함**.


2. **단어 정렬 및 통합**: 분리된 단어들을 정렬하고 동일 의미를 갖는 단어는 일원화.


3. **영문 명칭 및 약어 매핑**: 논리명에 대응하는 영문 물리명과 공통 약어(Abbreviation)를 부여하고 용어의 상세 의미를 기술.



#### (3) 명명 규칙 및 약어 표준화

* 복합 명사 조합 시 밑줄(`_`) 표기법 사용 (예: `이메일 수신 거부` $\rightarrow$ `email_rcv_deny`).


* 빈번하게 사용되거나 길이가 긴 영어 단어는 약어를 정하여 적용:


* `identifier` $\rightarrow$ `id`


* `number` $\rightarrow$ `no`


* `yes/no` $\rightarrow$ `yn`


* `information` $\rightarrow$ `info`


* `employee` $\rightarrow$ `emp`


* `department` $\rightarrow$ `dept`




* 완성된 용어사전의 물리명과 약어 규칙을 기반으로 최종 도메인 정의서(물리명 포함)를 완성.

### 4. 모델링 도구를 이용한 도메인 작성

* **erwin 도구 활용**: CASE 툴(erwin 등)의 도메인 관리 기능을 활용하여 표준 도메인 등록.


* 도메인 등록 시 도메인명, 물리명, 데이터 타입, 초기값(Default), 값의 범위(Check 제약조건)를 지정하여 모델 전반에 일관되게 상속/적용함 (예: 도메인명 `예아니오` / 물리명 `yes_no` / 데이터 타입 `char(1)` / 초기값 `'N'` / 값의 범위 `'Y', 'N'`).
