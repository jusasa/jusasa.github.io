제12장 **『암호학적 해시 함수(Cryptographic Hash Functions)』** 및 **『생일 역설(Birthday Paradox)』**의 핵심 내용을 정리해 드립니다.

---

### 1. 암호학적 해시 함수의 기본 개념과 특징
* **정의**: 임의 길이의 메시지(입력 데이터 $(M)$)를 고정된 길이의 해시 값($(h = H(M))$, 메시지 다이제스트)으로 변환하는 수학적 함수입니다.
* **주요 특징**:
  * **고정된 출력 길이**: 입력 데이터의 크기와 상관없이 항상 동일한 길이의 해시 값을 생성합니다.
  * **빠른 연산 속도**: 대량의 데이터도 빠르게 처리할 수 있습니다.
  * **비가역성(Irreversibility / 일방향성)**: 해시 값으로부터 원본 데이터를 역산해 복원하는 것은 계산적으로 불가능합니다.

---

### 2. 암호학적 해시 함수의 3대 보안 요구사항
* **선이미지 회피성 (Preimage Resistance / 일방향성)**: 주어진 해시 값 $(h)$에 대해 $(H(x) = h)$를 만족하는 원본 메시지 $(x)$를 찾는 것이 계산적으로 실행 불가능해야 합니다. (공격 복잡도: $(2^m)$)
* **2차 선이미지 회피성 / 약한 충돌 회피성 (Weak Collision Resistance)**: 특정 메시지 $(x)$가 주어졌을 때, $(H(x') = H(x))$를 만족하는 다른 메시지 $(x' (\neq x))$를 찾는 것이 계산적으로 실행 불가능해야 합니다.
* **강한 충돌 회피성 (Strong Collision Resistance)**: $(H(x) = H(x'))$를 만족하는 **서로 다른 임의의 두 메시지 쌍 $((x, x'))$**를 찾는 것이 계산적으로 실행 불가능해야 합니다.

---

### 3. 주요 응용 분야
* **메시지 인증 (Message Authentication)**: 데이터 전송 시 변조 여부(무결성)를 검증하기 위해 메시지 다이제스트를 활용합니다.
* **전자서명 (Digital Signature)**: 메시지 전체 대신 해시 값에 송신자의 개인키로 서명함으로써 연산 효율성을 높입니다.
* **시스템 무결성 및 보안**: 패스워드 일방향 저장, 파일 무결성 검사(바이러스 및 침입 탐지), 의사난수 생성기(PRNG) 등에 활용됩니다.

---

### 4. 해시 함수 설계 방식과 주요 알고리즘
* **머클-담가르트(Merkle-Damgård) 메타 구조**: 고정 길이의 압축 함수 $(f)$를 반복 적용하여 임의 길이 메시지를 처리하며, 패딩 블록에 메시지 비트 길이를 추가하는 **MD-Strengthening** 기법을 사용합니다.
* **블록 암호 기반 해시 함수**: 대칭 블록 암호를 활용하여 해시를 생성하며, 대표적으로 **Davies-Meyer**($(H_i = E_{M_i}(H_{i-1}) \oplus H_{i-1})$), **Rabin**, **Matyas-Meyer-Oseas**, **Miyaguchi-Preneel** 구조가 있습니다.
* **대표 알고리즘 발전 과정**:
  * **MD4 / MD5**: 초기 알고리즘으로, 현재는 충돌 취약성이 발견되어 사용되지 않습니다.
  * **SHA-1**: 160비트 해시 값을 출력하며 512비트 블록 단위로 처리합니다.
  * **SHA-2 (SHA-256 / SHA-512)**: SHA-512 기준 1024비트 블록을 입력받아 80라운드 압축 함수를 거쳐 512비트 다이제스트를 생성합니다.
  * **SHA-3 (Keccak)**: NIST 공모전(2012년)을 통해 선정된 스펀지(Sponge) 구조 기반의 최신 해시 표준입니다.

---

### 5. 생일 역설(Birthday Paradox)과 생일 공격(Birthday Attack)
* **생일 역설의 원리**: 무작위로 모인 **23명의 그룹**에서 최소 두 명의 생일이 같을 확률은 **50%($(1/2)$) 이상**($(\approx 50.7\%)$)이 됩니다.
* **암호학적 적용 (생일 공격)**:
  * 출력 해시 값의 길이가 $(n)$비트일 때(가능한 가짓수 $(N = 2^n)$), 무작위로 **약 $(q \approx 1.17 \times \sqrt{N} = 1.17 \times 2^{n/2})$개**의 해시를 계산하면 50% 확률로 충돌쌍을 찾을 수 있습니다.
  * **보안적 의미**: 생일 공격으로 인해 해시 함수의 **강한 충돌 회피성을 깨뜨리는 공격 복잡도가 $(2^n)$에서 $(2^{n/2})$으로 크게 감소**합니다.
  * **해시 길이 기준**:
    * **128비트 해시**: 생일 공격 시 $(2^{64})$번 연산으로 충돌을 찾을 수 있어 보안상 취약합니다.
    * **256비트 이상 해시**: 충돌 탐지에 $(2^{128})$번 연산이 필요하므로 현재 안전한 것으로 평가받습니다.

### 1. 메타 방법(Meta Method) 및 머클-담가르트(Merkle-Damgård) 구조

해시 함수는 가변 길이의 긴 메시지를 다루기 위해 **고정 크기의 입력**을 처리하는 **기초 압축 함수(Compression Function, $(f)$)를 반복 적용**하는 **메타 설계 구조**를 채택합니다.

* **기초 연산 흐름**:
  1. 전체 메시지를 고정된 블록 크기($(M_0, M_1, \dots, M_{t-1})$)로 나눕니다.
  2. 사전 약속된 초기값 $(H_0)$을 설정합니다.
  3. 이전 단계의 출력 $(H_{i-1})$과 현재 메시지 블록 $(M_{i-1})$을 압축 함수 $(f)$의 입력으로 넣어 다음 단계의 연산값 $(H_i = f(H_{i-1}, M_{i-1}))$를 구합니다.
  4. 마지막 블록까지 처리한 최종 $(H_t)$가 최종 **해시 다이제스트(Hash Digest)**가 됩니다.
* **MD-Strengthening (패딩 보강)**:
  * 메시지 길이를 블록 단위 배수로 맞추는 패딩(Padding) 작업 시, **마지막 패딩 블록에 원래 메시지의 전체 비트 길이를 명시적으로 추가**하는 기법입니다.
  * 압축 함수 $(f)$가 충돌 회피성을 만족하면 전체 해시 함수 $(H)$ 역시 강한 충돌 회피성을 유지할 수 있도록 정밀하게 설계되었습니다.

### 2. 블록 암호 기반 해시 함수 (Block Cipher-based Hash Functions)

기존 대칭키 블록 암호 알고리즘(DES, AES 등)을 압축 함수로 재활용하여 구현하는 방식입니다. 입력 위치와 XOR(비트 단위 배타적 논리합) 피드백 구조에 따라 4가지 대표 방식으로 나뉩니다.

* **Rabin 기법**:
  * 메시지 블록 $(M_i)$를 **암호화 키 $(K)$**로 사용하고, 이전 단계 해시값 $(H_{i-1})$을 **평문 $(P)$** 위치에 넣어 암호화합니다.
  * **수식**: $(H_i = E_{M_i}(H_{i-1}))$
  * **한계**: 피드백 연산이 없어 중간자 공격(Man-in-the-middle attack)에 취약합니다.
* **Davies-Meyer 기법**:
  * Rabin 방식에 **이전 해시값 $(H_{i-1})$을 덧셈(XOR) 피드백**하는 요소를 추가한 구조입니다.
  * 메시지 블록 $(M_i)$를 키 $(K)$로 사용해 $(H_{i-1})$을 암호화한 후, 그 결과에 $(H_{i-1})$을 XOR합니다.
  * **수식**: $(H_i = E_{M_i}(H_{i-1}) \oplus H_{i-1})$
* **Matyas-Meyer-Oseas 기법**:
  * Davies-Meyer와 반대로 **이전 해시값 $(H_{i-1})$을 키 $(K)$**로 사용하고, **메시지 블록 $(M_i)$를 평문 $(P)$**에 입력받아 암호화한 뒤 $(M_i)$와 XOR합니다.
  * **수식**: $(H_i = E_{H_{i-1}}(M_i) \oplus M_i)$
* **Miyaguchi-Preneel 기법**:
  * Matyas-Meyer-Oseas 기법을 더욱 강화하여, 암호화 결과에 **평문 블록 $(M_i)$와 이전 해시값 $(H_{i-1})$을 모두 XOR 피드백**합니다.
  * **수식**: $(H_i = E_{H_{i-1}}(M_i) \oplus M_i \oplus H_{i-1})$
* **Whirlpool**:
  * 블록 암호 기법을 확장 설계한 대표적인 독립 해시 알고리즘 중 하나입니다.

### 3. 전용 해시 함수 알고리즘 (Dedicated Hash Algorithms)

블록 암호를 변용하지 않고, 해시 처리만을 목적으로 전용 설계된 알고리즘들입니다.

#### (1) MD4 / MD5
* 1990년 Ronald Rivest가 제안한 대표적인 초창기 전용 해시 함수입니다.
* 메시지에 64비트 길이 정보를 첨부하여 512비트 블록 단위로 3라운드 연산을 수행합니다.
* 현재는 **수학적 충돌 취약점**이 발견되어 암호학적으로 사용이 중지(Broken)되었습니다.

#### (2) SHA-1 (Secure Hash Algorithm 1)
* 1995년 미국 NIST에 의해 FIPS 180-1 표준으로 공포되었습니다.
* **스펙**: 입력 메시지는 $(2^{64})$비트 미만, **출력 다이제스트는 160비트**, 입력 단위는 **512비트 블록 (32비트 워드 $(\times)$ 16개)**입니다.
* **동작 구동**:
  1. 초기 상태 5개의 32비트 버퍼($(A, B, C, D, E)$)를 상수로 초기화합니다.
  2. 16개 워드 메세지를 논리 XOR 확산 과정을 거쳐 **80개 워드($(W_0 \sim W_{79})$)**로 확장합니다.
  3. 총 **80단계(라운드)** 동안 비선형 논리 함수 및 순환 시프트 연산을 적용해 버퍼를 갱신합니다.
* **상태**: 탐색 기술 발달로 충돌 위험성이 증가함에 따라 단계적 파기가 진행 중입니다.

#### (3) SHA-2 시리즈 (SHA-256 / SHA-512)
* SHA-1의 구조를 발전시켜 출력 크기를 늘린 FIPS 180-2 표준 알고리즘입니다.
* **SHA-256**: 512비트 블록 입력 $(\rightarrow)$ 256비트 출력, 64단계 라운드.
* **SHA-512**:
  * **입력 블록 크기**: **1024비트 (64비트 워드 $(\times)$ 16개)**.
  * **출력 크기**: **512비트 다이제스트**.
  * **내부 연산**: 8개의 64비트 버퍼($(a, b, c, d, e, f, g, h)$)를 사용하며, 80단계 라운드 동안 64비트 덧셈 상수 $(K_t)$와 확장 메시지 워드 $(W_t)$를 더해 버퍼 상태를 갱신합니다.

#### (4) SHA-3 (Keccak)
* NIST가 SHA-2의 보안 우려에 대비해 개최한 공개 공모전을 거쳐 2012년 10월 선정된 **최신 해시 표준 (FIPS 202)**입니다.
* Guido Bertoni, Joan Daemen, Michaël Peeters, Gilles Van Assche가 설계한 **Keccak 알고리즘** 기반입니다.
* 기존 머클-담가르트 구조와 달리 **스펀지(Sponge) 구조**라는 새로운 비선형 치환 매커니즘을 적용하여 높은 보안성 및 하드웨어 연산 효율성을 보장합니다.

암호학적 해시 함수 $(H)$는 임의 길이의 메시지 $(M)$을 입력받아 고정된 길이의 해시 값 $(h = H(M))$을 출력하는 수학적 일방향 함수입니다. 정보보호 및 암호학 분야에서 데이터 무결성 검증, 메시지 인증, 전자서명 등에 안전하게 활용되기 위해 요구되는 **7가지 핵심 요구사항** 및 보안적 성질은 다음과 같습니다.

---

### 1. 기본적 기능 및 효율성 요구사항 (Basic & Operational Requirements)

1. **다양한 입력 길이 (Variable Input Size)**
   * 해시 함수 $(H)$는 어떠한 크기의 데이터 블록(임의의 가변 길이 메시지)에도 문제없이 적용될 수 있어야 합니다.
2. **고정된 출력 길이 (Fixed Output Size)**
   * 입력 데이터의 크기나 길이에 상관없이, 해시 함수 $(H)$는 항상 미리 정해진 고정된 크기(예: SHA-256의 경우 256비트)의 해시 코드(다이제스트)를 생성해야 합니다.
3. **효율성 (Efficiency)**
   * 임의의 입력 $(x)$에 대해 $(H(x))$를 계산하는 과정이 실질적으로 하드웨어 및 소프트웨어 환경에서 모두 구현하기 용이해야 하며, 계산 속도가 비교적 수월하고 빨라야 합니다.
4. **의사 난수성 (Pseudorandomness)**
   * 해시 함수 $(H)$의 출력값은 통계적으로 무작위 수열처럼 보여야 하며, 의사난수성에 대한 표준 시험 기준을 만족해야 합니다.

---

### 2. 핵심 보안 요구사항 (Security Requirements & Collision Resistances)

암호 분석적인 공격으로부터 안전성을 보장하기 위해 요구되는 3대 핵심 보안 성질입니다.

5. **선이미지 회피성 (Preimage Resistance / 일방향성, One-Wayness)**
   * **개념**: 임의의 해시 값 $(h)$가 주어졌을 때, $(H(x) = h)$를 만족하는 원본 입력 $(x)$를 찾는 것이 계산적으로 실행 불가능(Infeasible)해야 합니다.
   * **의미**: 해시 값만 보고 원본 메시지를 역산하여 알아내는 공격을 방지합니다.
   * **공격 복잡도**: $(m)$비트 해시 코드에 대해 전사적 공격(Brute-force)으로 선이미지를 찾으려면 약 $(2^m)$번의 연산 노력이 필요합니다.

6. **2차 선이미지 회피성 (Second Preimage Resistance / 약한 충돌 회피성, Weak Collision Resistance)**
   * **개념**: 특정 입력 메시지 $(x)$가 미리 주어졌을 때, $(H(y) = H(x))$를 만족하는 서로 다른 메시지 $(y \; (\neq x))$를 찾는 것이 계산적으로 실행 불가능해야 합니다.
   * **의미**: 기존의 정당한 메시지 $(x)$를 동일한 해시 값을 가지는 위조 메시지 $(y)$로 바꿔치기하는 공격을 막아줍니다.
   * **공격 복잡도**: $(m)$비트 해시 코드에 대해 전사적 공격으로 2차 선이미지를 찾기 위한 연산 복잡도는 약 $(2^m)$에 비례합니다.

7. **충돌 회피성 (Collision Resistance / 강한 충돌 회피성, Strong Collision Resistance)**
   * **개념**: $(H(x) = H(y))$를 만족하는 **서로 다른 임의의 두 입력 쌍 $((x, y))$**를 찾는 것이 계산적으로 실행 불가능해야 합니다.
   * **의미**: 입력값이 미리 지정되지 않은 상태에서, 해시 값이 같은 임의의 두 메시지 조합(충돌쌍)을 사전에 찾아내는 공격을 방지합니다.
   * **공격 복잡도**: 확률 이론의 **생일 역설(Birthday Paradox)**에 기반한 생일 공격(Birthday Attack)으로 인해, $(m)$비트 해시 코드에서 충돌쌍을 찾아내는 공격 복잡도는 $(2^m)$이 아니라 **$(2^{m/2})$**로 대폭 감소합니다.

### 3. 약한 충돌 회피성 vs 강한 충돌 회피성 비교

| 구분 | **약한 충돌 회피성 (2차 선이미지 회피성)** | **강한 충돌 회피성 (충돌 회피성)** |
| :--- | :--- | :--- |
| **입력 조건** | 특정 입력 $(x)$가 **미리 주어짐** | 입력 $(x, y)$ 모두 **자유롭게 선택 가능** |
| **공격 목표** | $(H(y) = H(x))$인 $(y \; (\neq x))$ 찾기 | $(H(x) = H(y))$인 임의의 쌍 $((x, y))$ 찾기 |
| **공격 복잡도** | **$(2^m)$** (상대적으로 탐색이 어려움) | **$(2^{m/2})$** (생일 공격으로 탐색이 상대적으로 쉬움) |

---

**SHA(Secure Hash Algorithm)**는 미국 표준기술연구소(NIST)에서 제정한 대표적인 암호학적 해시 알고리즘 표준군으로, 입력 메시지 크기에 관계없이 고정된 길이의 메시지 다이제스트(Message Digest)를 생성합니다.

---

### 1. SHA의 발전 역사 및 표준 제정 과정
* **SHA-0 (1993년)**: NIST에서 **FIPS PUB 180**으로 최초 공포된 해시 표준 알고리즘입니다.
* **SHA-1 (1995년)**: SHA-0의 결함을 보완하여 **FIPS 180-1**로 개정되었으며, **160비트** 해시 다이제스트를 생성합니다. 암호 분석 기술의 발전에 따라 2030년까지 단계적으로 사용이 중지될 예정입니다.
* **SHA-2 (2002년 ~ 2008년)**: **FIPS 180-2**를 통해 **SHA-256, SHA-384, SHA-512**가 공포되었으며, 이후 **FIPS 180-3**(2008년)에서 **SHA-224**가 추가되었습니다. SHA-1과 동일한 기본 구조, 모듈라 연산, 논리 연산을 공유하지만 다이제스트 길이를 늘려 보안성을 대폭 강화했습니다.
* **SHA-3 (2012년 / 2015년)**: SHA-2의 잠재적 구조적 우려에 대비해 NIST 공개 공모전(2007~2012년)을 거쳐 **Keccak 알고리즘**이 최종 선정되었으며, **FIPS 202**(2015년) 표준으로 제정되었습니다.

---

### 2. SHA 버전별 상세 규격 비교 (FIPS 180-4)

| 알고리즘 | 메시지 다이제스트 크기 (bit) | 최대 메시지 크기 (bit) | 블록 크기 (bit) | 워드 크기 (bit) | 단계(라운드) 수 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **SHA-1** | **160** | $(< 2^{64})$ | **512** | 32 | **80** |
| **SHA-224** | **224** | $(< 2^{64})$ | **512** | 32 | **64** |
| **SHA-256** | **256** | $(< 2^{64})$ | **512** | 32 | **64** |
| **SHA-384** | **384** | $(< 2^{128})$ | **1024** | 64 | **80** |
| **SHA-512** | **512** | $(< 2^{128})$ | **1024** | 64 | **80** |

*(※ 모든 크기의 단위는 비트 기준입니다.)*

---

### 3. 주요 알고리즘 동작 구조

#### ① SHA-1
* **패딩(Padding) 및 블록 분할**: 입력 메시지 $(L)$비트 뒤에 `1`비트와 `0`을 채워 $(L+k \equiv 448 \pmod{512})$로 맞춘 후, 메시지 원본 길이 $(L)$을 나타내는 **64비트 필드**를 덧붙여 **512비트 블록 단위**로 처리합니다.
* **버퍼 초기화**: 5개의 32비트 버퍼 **$(CV = [A, B, C, D, E])$**를 정해진 상수로 초기화합니다.
* **메시지 워드 확장 (Diffusion)**: 16개 32비트 워드($(W_0 \sim W_{15})$)를 XOR 논리 연산을 통해 **80개 워드($(W_0 \sim W_{79})$)**로 확장합니다 ($(W_t = W_{t-3} \oplus W_{t-8} \oplus W_{t-14} \oplus W_{t-16})$).
* **80단계 압축 연산**: 20단계씩 4개 라운드로 나뉘어 비선형 함수, 순환 이동(Circular Shift), 덧셈 상수를 적용하여 버퍼 상태를 갱신합니다.

#### ② SHA-512
* **입력 규격**: $(< 2^{128})$비트 미만의 메시지를 **1024비트 블록** 단위로 나누어 처리합니다.
* **압축 함수 ($(F)$) 연산**:
  * 8개의 64비트 버퍼 **$((a, b, c, d, e, f, g, h))$**를 사용하여 총 **512비트 버퍼 상태**를 유지·갱신합니다.
  * 총 **80단계(라운드)** 동안 현재 메시지 블록에서 유도된 64비트 워드 $(W_t)$와 덧셈 상수 $(K_t)$를 적용하고, $(\bmod 2^{64})$ 덧셈 연산을 수행합니다.

---

### 4. SHA-3 (Keccak)의 특징
* **설계자**: Guido Bertoni, Joan Daemen, Michaël Peeters, Gilles Van Assche가 공동 설계했습니다.
* **스펀지(Sponge) 구조**: 기존 SHA-1/SHA-2의 머클-담가르트(Merkle-Damgård) 구조와 달리, **스펀지 구조 기반의 순열 메커니즘**을 채택하여 동일한 해시 크기에서도 선이미지 회피성 및 충돌 회피성에 대해 이론적 최대치에 가까운 높은 보안 강도를 제공합니다.
* **유연성 및 교체 용이성**: 다양한 하드웨어 및 소프트웨어 플랫폼에서 메모리와 처리 시간 효율성이 뛰어나며, 기존 SHA-2를 손쉽게 대체할 수 있도록 설계되었습니다.
