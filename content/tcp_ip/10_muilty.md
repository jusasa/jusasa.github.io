### 📌 1. 다중 접속 서버(Concurrent Server)의 3가지 구현 방식

둘 이상의 클라이언트에게 동시에 접속을 허용하여 서비스를 제공하는 서버 모델은 크게 세 가지로 나뉩니다:

| 구현 방식 | 핵심 원리 및 동작 |
| --- | --- |
| **멀티프로세스 기반 서버** | 클라이언트 연결 요청마다 **새로운 프로세스를 생성(`fork`)**하여 서비스를 제공 |
| **멀티플렉싱 기반 서버** | 하나의 프로세스가 **여러 개의 소켓(입출력 대상)을 묶어서 관리**하며 서비스 제공 (`select` 등) |
| **멀티쓰레딩 기반 서버** | 하나의 프로세스 내에서 클라이언트 수만큼 **경량화된 쓰레드(Thread)를 생성**하여 서비스 제공 |

### 📌 2. 프로세스와 `fork()` 함수

#### (1) 프로세스(Process)와 PID

* **프로세스 정의**: 실행 중인 프로그램. 프로그램 실행에 필요한 메모리(Code, Data, Heap, Stack)와 시스템 리소스를 총칭합니다.
* **프로세스 ID (PID)**: 운영체제가 생성되는 모든 프로세스를 식별하기 위해 부여하는 고유 정수 번호입니다 (터미널에서 `ps au` 명령어로 확인 가능).

#### (2) `fork()` 함수 호출을 통한 프로세스 생성

```c
#include <unistd.h>

pid_t fork(void);
// 성공 시: 부모 프로세스에게는 자식 PID, 자식 프로세스에게는 0 반환
// 실패 시: -1 반환

```

* **동작 원리 (메모리 복사)**:
* `fork()`가 호출되면 호출한 부모 프로세스의 **모든 메모리 공간(Data, Stack, Heap 등)을 그대로 복제**하여 자식 프로세스를 생성합니다.
* 복사 이후부터는 부모와 자식이 **완전히 독립된 프로세스로 각자의 길을 실행**합니다.


* **반환값(Return Value)에 따른 분기 (★ 핵심)**:
* **부모 프로세스**: 생성된 **자식 프로세스의 PID**를 반환받음 (`pid > 0`)
* **자식 프로세스**: `0`을 반환받음 (`pid == 0`)


* **독립된 메모리 공간의 증명 (`fork.c`)**:
* 부모와 자식은 메모리를 공유하지 않고 독립되어 있으므로, 자식 프로세스에서 변수(`gval`, `lval`)를 수정해도 부모 프로세스의 변수 값에는 전혀 영향을 주지 않습니다.

### 📌 3. 좀비 프로세스 (Zombie Process)

#### (1) 좀비 프로세스란?

* **실행이 완료(종료)되었음에도 불구하고, 커널 메모리 상에서 소멸되지 않고 남아있는 프로세스**입니다.
* 시스템의 리소스(PID, 프로세스 테이블 등)를 지속적으로 점유하여 시스템 성능 저하를 초래합니다.

#### (2) 좀비 프로세스의 생성 원인

1. 자식 프로세스는 종료 시 종료 상태 값(`exit()`의 인자값 또는 `main()`의 `return` 값)을 운영체제(커널)에 전달합니다.
2. 커널은 **부모 프로세스가 이 종료 상태 값을 회수(수거)해 갈 때까지 자식 프로세스를 완전히 소멸시키지 않고 최소 정보(종료 상태)를 유지**합니다.
3. **부모 프로세스가 종료 값을 요구하는 시스템 콜(함수)을 호출하지 않고 방치**하면, 자식 프로세스는 **좀비 프로세스**가 됩니다.

#### (3) 좀비 프로세스 확인 (`zombie.c`)

* 부모 프로세스가 `sleep(30)` 등으로 대기하는 동안, 자식 프로세스가 먼저 종료되면 자식은 좀비 상태가 됩니다.
* 터미널에서 `ps au`를 실행하면 좀비 프로세스는 다음과 같이 표시됩니다:
* **`STAT`**: **`Z`** 또는 **`Z+`**
* **`COMMAND`**: **`[zombie] <defunct>`** (사멸된 상태)


* ⚠️ **참고**: 부모 프로세스가 완전히 종료되면, 고아가 된 좀비 자식 프로세스도 부모와 함께 비로소 소멸됩니다.

### 📌 4. 좀비 프로세스의 소멸 1: `wait()` 함수

부모 프로세스가 자식 프로세스의 반환값을 운영체제에 요청하여 좀비를 방지/소멸시키는 표준 함수입니다.

```c
#include <sys/types.h>
#include <sys/wait.h>

pid_t wait(int *status);
// 성공 시: 종료된 자식 프로세스의 PID 반환
// 실패 시(자식 프로세스가 없는 경우): -1 반환

```

#### (1) `wait()` 함수의 특징과 한계

* **장점**: 사용 방법이 매우 직관적이고 간단합니다.
* **단점 (Blocking)**: 호출 시점에 이미 종료된 자식 프로세스가 없다면, **자식 프로세스가 종료될 때까지 부모 프로세스는 무한 대기(블로킹, Blocking) 상태에 빠집니다**. (서버의 주 업무가 멈출 위험 존재)

#### (2) 자식의 종료 상태 확인 매크로 함수 (★ 시험 단골 출제)

`wait()` 함수의 인자로 전달된 정수 포인터(`status`)에는 종료 상태뿐만 아니라 다양한 시스템 비트 정보가 함께 포함되어 있으므로, 매크로 함수를 거쳐 해석해야 합니다.

* **`WIFEXITED(status)`**: 자식 프로세스가 정상적으로 종료되었으면 참(`true`)을 반환합니다.
* **`WEXITSTATUS(status)`**: 정상 종료된 자식 프로세스가 반환한 값(`exit(val)`의 `val` 또는 `return val`의 `val`)을 온전히 추출해 반환합니다.

```c
int status;
pid_t child_pid = wait(&status);

if (WIFEXITED(status)) {
    printf("자식 정상 종료, 반환값: %d \n", WEXITSTATUS(status));
}

```

### 📝 10-1 실전 시험 족집게 체크리스트

1. **`fork()` 반환값 구분**: 부모에게는 **자식의 PID**, 자식에게는 **`0`**, 에러 시 **`-1`**.
2. **부모/자식 메모리**: 코드 및 데이터 영역을 복제하지만, 복제 이후는 **완전히 독립된 메모리 공간**을 가짐 (변수 공유 불가).
3. **좀비 프로세스 원인**: 자식 프로세스가 종료되면서 반환한 상태값을 **부모 프로세스가 읽어가지(회수하지) 않아서 발생**.
4. **`ps au` 상의 좀비 표기**: `STAT` 컬럼의 **`Z`** 및 `COMMAND`의 **`<defunct>`**.
5. **자식 종료값 확인 매크로**: 정상 종료 판별은 **`WIFEXITED`**, 실제 반환값 추출은 **`WEXITSTATUS`**.

**`fork()` 함수**에 대한 핵심 설명과 원리 정리입니다.

### 📌 1. `fork()` 함수란?

* **정의**: 실행 중인 프로세스(부모 프로세스)가 자신과 똑같은 **복사본 프로세스(자식 프로세스)를 생성**할 때 사용하는 시스템 호출 함수입니다.


* **헤더 및 함수 원형**:
```c
#include <unistd.h>

pid_t fork(void);

```



---

### 📌 2. `fork()` 함수의 반환값(Return Value)과 흐름 분기

`fork()`가 한 번 호출되면, 호출 이후부터는 **부모 프로세스와 자식 프로세스 2개의 독립적인 흐름이 동시에 실행**됩니다.
두 프로세스는 **반환값(`pid`)의 차이**를 통해 자신이 부모인지 자식인지 구분하여 각자의 코드를 수행합니다.

| 호출 주체 | `fork()`의 반환값 | 의미 |
| --- | --- | --- |
| **부모 프로세스 (Parent)** | **생성된 자식 프로세스의 PID** (`> 0`) | 자식 프로세스를 식별 및 관리하기 위해 자식의 PID를 받음

 |
| **자식 프로세스 (Child)** | **`0`** | 자신이 새로 생성된 자식임을 인식

 |
| **실패 시** | **`-1`** | 메모리 부족 등으로 프로세스 생성 실패

 |

#### 💻 실행 흐름 분기 코드 형태

```c
pid_t pid = fork();

if (pid < 0) {
    // fork 실패 에러 처리[cite: 1]
} else if (pid == 0) {
    // 자식 프로세스 루틴 실행 (pid == 0)[cite: 1]
} else {
    // 부모 프로세스 루틴 실행 (pid != 0, 자식의 PID를 가짐)[cite: 1]
}

```

### 📌 3. 메모리 복사와 독립성

* **완전한 메모리 복사**:
* `fork()`가 성공하면, 자식 프로세스는 부모 프로세스의 **코드, 데이터(Data), 힙(Heap), 스택(Stack) 영역 등 모든 메모리 상태를 그대로 복제**받습니다.




* **독립적인 실행 (메모리 비공유)**:
* 복사 이후 두 프로세스는 **완전히 독립된 프로그램**으로 동작합니다.


* 따라서 자식 프로세스에서 변수 값을 변경하더라도, 부모 프로세스의 변수에는 **전혀 영향을 주지 않습니다**.





> **예제(`fork.c`) 동작 분석**:
>
>
> * `fork()` 호출 전: `gval = 11`, `lval = 25`
>
>
> * 자식 프로세스 (`pid == 0`): `gval += 2`, `lval += 2`  👉 **`[13, 27]`** 출력
>
>
> * 부모 프로세스 (`pid != 0`): `gval -= 2`, `lval -= 2`  👉 **`[9, 23]`** 출력
>
>
>
>

### 📌 4. 소켓 프로그래밍에서의 `fork()` (디스크립터 복사)

멀티프로세스 기반 다중 접속 서버(`echo_mpserv.c`)에서 `fork()`를 사용할 때의 핵심 주의사항입니다:

1. **소켓 자체가 아닌 "파일 디스크립터"가 복사됨**:
* 소켓은 운영체제(커널)가 소유하며, 부모와 자식 프로세스에는 **해당 소켓을 가리키는 파일 디스크립터(포인터 역할)만 복사**됩니다.




2. **소켓 소멸 조건**:
* 하나의 소켓을 두 개 이상의 파일 디스크립터가 가리키고 있을 경우, **가리키는 모든 디스크립터가 `close()`되어야 소켓이 완전히 소멸**합니다.




3. **불필요한 디스크립터 종료 필수**:


* **부모 프로세스**: 연결 수락(`accept`) 후 클라이언트 소켓(`clnt_sock`) 디스크립터를 즉시 닫아야 함 (자식이 전담하므로).


* **자식 프로세스**: 서비스 시작 전 서버 리스닝 소켓(`serv_sock`) 디스크립터를 즉시 닫아야 함 (부모가 계속 연결 요청을 받아야 하므로).
