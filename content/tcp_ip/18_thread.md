### 📌 1. 쓰레드의 이론적 이해 (18-1)

#### (1) 쓰레드의 등장 배경

기존 멀티프로세스 방식은 다음과 같은 구조적 한계를 가집니다:

* **프로세스 생성 및 스위칭 비용**: 프로세스 생성 시 많은 리소스가 소모되며, 프로세스 간 컨텍스트 스위칭(Context Switching)으로 인한 성능 저하가 발생합니다.
* **데이터 교환의 어려움**: 프로세스 간 메모리가 완전히 독립되어 있으므로 데이터 공유가 불가능하며, 별도의 IPC(Inter-Process Communication) 기법이 필요합니다.

#### (2) 프로세스 vs 쓰레드 구조 비교

* **경량화된 프로세스**: 쓰레드는 프로세스 내부에서 프로그램의 실행 흐름을 추가하는 단위로, 프로세스보다 생성 및 컨텍스트 스위칭이 훨씬 빠릅니다.
* **메모리 구조 차이**:
* **공유 영역**: **데이터(Data) 영역(전역 변수), 힙(Heap) 영역, 코드(Code) 영역**은 프로세스 내의 모든 쓰레드가 공유하므로 별도의 IPC 없이 직접 데이터를 주고받을 수 있습니다.
* **독립 영역**: 각 쓰레드는 함수 호출과 지역 변수 관리를 위해 **스택(Stack) 영역만 독립적으로 할당**받습니다.

### 📌 2. 쓰레드의 생성, 실행 및 소멸 (18-2)

리눅스 환경에서 POSIX 표준 쓰레드 라이브러리(`-lpthread` 옵션으로 컴파일)를 사용합니다.

#### (1) 쓰레드 생성: `pthread_create()`

```c
#include <pthread.h>

int pthread_create(
    pthread_t *restrict thread,              // 생성할 쓰레드 ID 저장 변수 포인터
    const pthread_attr_t *restrict attr,     // 쓰레드 특성 정보 (보통 NULL 전달)
    void *(*start_routine)(void *),          // 쓰레드의 main 역할을 할 함수 포인터
    void *restrict arg                       // 쓰레드 함수에 전달할 인자 포인터
);
// 성공 시 0, 실패 시 0 이외의 값 반환

```

#### (2) 쓰레드 종료 대기: `pthread_join()`

* **역할**: `main()` 함수가 먼저 종료되어 프로세스 전체가 소멸하는 것을 막기 위해, 지정한 쓰레드가 종료될 때까지 호출한 쓰레드를 블로킹(대기) 상태로 둡니다.
* 쓰레드 함수가 반환(`return`)하는 값을 두 번째 인자(`status`)로 받아올 수 있으며, 종료된 쓰레드의 리소스를 회수합니다.

```c
int pthread_join(pthread_t thread, void **status);
// 성공 시 0, 실패 시 0 이외의 값 반환

```

#### (3) 쓰레드 자동 소멸(분리): `pthread_detach()` (★ 서버 구현 핵심)

* `pthread_join()`은 쓰레드가 끝날 때까지 호출 측이 블로킹되므로, 계속 새로운 클라이언트를 `accept()`해야 하는 서버에서는 사용하기 어렵습니다.
* `pthread_detach(t_id)`를 호출하면, 해당 쓰레드가 실행을 완료했을 때 **블로킹 대기 없이 커널이 쓰레드 리소스를 자동으로 소멸**시킵니다. (단, `detach` 이후에는 `pthread_join` 호출 불가)

### 📌 3. 쓰레드 안전(Thread-safe)과 임계영역 (18-3)

#### (1) 쓰레드 안전 함수 (Thread-safe vs Thread-unsafe)

* **Thread-safe 함수**: 둘 이상의 쓰레드가 동시에 호출해도 문제를 일으키지 않는 함수.
* **Thread-unsafe 함수**: 내부적으로 전역/정적(static) 변수를 사용하여 동시 호출 시 데이터가 덮어씌워지는 함수 (예: `gethostbyname()` 등).
* 컴파일 시 **`-D_REENTRANT`** 옵션을 주면 불안전한 함수를 쓰레드 안전 함수(`_r` 접미사 버전 등)로 자동 치환해 줍니다.



#### (2) 전역변수 동시접근 문제와 임계영역 (Critical Section)

* **임계영역 정의**: **둘 이상의 쓰레드가 동시에 실행하면 문제를 일으키는 코드 영역**을 말합니다.
* **발생 원리 (`thread4.c` 분석)**:
* 전역변수 `num`에 대해 `num += 1`과 `num -= 1`을 각각 5천만 번씩 수행해도 결과는 `0`이 나오지 않습니다.
* CPU가 메모리의 `num` 값을 레지스터로 읽어와 연산한 뒤 다시 메모리에 저장하는 찰나에 컨텍스트 스위칭이 일어나 다른 쓰레드가 값을 덮어쓰기 때문입니다.
* 서로 다른 문장(`num += 1`과 `num -= 1`)이라도 동일한 공유 자원에 접근한다면 모두 임계영역으로 묶어야 합니다.

### 📌 4. 쓰레드 동기화 (Synchronization) (18-4)

쓰레드 동기화는 **(1) 동일한 메모리 영역으로의 동시 접근 차단**과 **(2) 쓰레드 간의 실행 순서 지정**이라는 두 가지 측면을 해결합니다.

#### (1) 뮤텍스 (Mutex: Mutual Exclusion) — 상호 배제

한 번에 하나의 쓰레드만 임계영역에 들어가도록 자물쇠(`Lock`/`Unlock`)를 채우는 기법입니다.

```c
#include <pthread.h>

pthread_mutex_t mutex;

pthread_mutex_init(&mutex, NULL);   // 뮤텍스 생성 및 초기화
pthread_mutex_lock(&mutex);         // 임계영역 진입 (잠금: 이미 잠겨있으면 풀릴 때까지 대기)
// [임계영역 코드]
pthread_mutex_unlock(&mutex);       // 임계영역 탈출 (잠금 해제)
pthread_mutex_destroy(&mutex);      // 뮤텍스 소멸

```

#### (2) 세마포어 (Semaphore) — 접근 제어 및 실행 순서 동기화

`0`과 `1`로 이루어진 바이너리 세마포어를 활용하면 쓰레드 간의 실행 순서(생산자-소비자 패턴 등)를 정교하게 제어할 수 있습니다.

```c
#include <semaphore.h>

sem_t sem;

sem_init(&sem, 0, 1);   // 세마포어 생성 (두 번째 인자 0: 프로세스 내부 공유, 세 번째 인자: 초기값)
sem_wait(&sem);         // 세마포어 값을 1 감소 (현재 값이 0이면 1 이상이 될 때까지 블로킹 대기)
// [임계영역 코드]
sem_post(&sem);         // 세마포어 값을 1 증가
sem_destroy(&sem);      // 세마포어 소멸

```

* **실행 순서 제어 원리**: 세마포어 A(초기값 `0`), 세마포어 B(초기값 `1`)를 두고 `read` 쓰레드와 `accu` 쓰레드가 교차로 `sem_wait`와 `sem_post`를 호출하면 **입력 ➡️ 누적 ➡️ 입력 ➡️ 누적** 순서를 강제할 수 있습니다.

### 📌 5. 멀티쓰레드 기반 다중접속 채팅 서버/클라이언트 구현 (18-5)

#### (1) 채팅 서버 구조 (`chat_server.c`)

* **공유 자원(임계영역 대상)**: 접속한 클라이언트 소켓 배열 `int clnt_socks[256];`과 총 접속자 수 `int clnt_cnt = 0;`.
* **동기화 적용 구간 (하나의 뮤텍스 `mutx`로 3곳을 모두 보호)**:
1. `main()`에서 새 클라이언트 연결 수락(`accept`) 후 `clnt_socks` 배열에 소켓을 추가할 때
2. `send_msg()`에서 `clnt_socks` 배열을 순회하며 모든 클라이언트에게 메시지를 전송(`write`)할 때 (전송 도중 소켓이 추가/삭제되는 것을 방지)
3. `handle_clnt()`에서 클라이언트 연결 종료(`read == 0`) 시 `clnt_socks` 배열에서 해당 소켓을 제거하고 `clnt_cnt--` 할 때


* **쓰레드 생성 및 분리**: `pthread_create()`로 클라이언트 전담 쓰레드(`handle_clnt`)를 생성한 직후 `pthread_detach(t_id)`를 호출하여 통신 종료 시 자동 소멸되도록 설계합니다.

#### (2) 채팅 클라이언트 구조 (`chat_client.c`)

* 하나의 소켓(`sock`)을 공유하면서 **입출력 분리를 위해 2개의 쓰레드**를 생성합니다:
* **송신 전용 쓰레드 (`send_msg`)**: 키보드 입력(`fgets`)을 받아 서버로 전송(`write`).
* **수신 전용 쓰레드 (`recv_msg`)**: 서버로부터 오는 메시지(`read`)를 받아 화면에 출력(`fputs`).


* `main()`에서는 두 쓰레드가 종료될 때까지 `pthread_join()`으로 대기한 후 소켓을 닫습니다.

### 📝 Chapter 18 시험 족집게 체크리스트

1. **쓰레드 메모리 구조**: **Data, Heap, Code는 공유**, **Stack만 독립 할당**.
2. **서버 쓰레드 소멸 처리**: `accept()` 루프에서 블로킹을 피하기 위해 `pthread_detach()`를 호출해 자동 소멸시킴.
3. **임계영역 정의**: 둘 이상의 쓰레드가 동시에 실행하면 문제를 일으키는 코드 영역 (서로 다른 함수/문장이라도 같은 전역자원에 접근하면 임계영역).
4. **동기화 수단 비교**: 동시 접근 차단에는 **뮤텍스(`pthread_mutex_lock`/`unlock`)**, 실행 순서 제어까지 필요할 때는 **세마포어(`sem_wait`/`sem_post`)** 활용.
5. **`chat_server.c` 동기화 핵심**: `clnt_socks` 배열에 추가(accept), 참조(send_msg), 삭제(handle_clnt)하는 세 영역 모두 동일한 뮤텍스로 보호해야 함.
